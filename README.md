# agent-kit

A personal, reusable kit of AI-agent tooling — skills, commands, and later subagents — that works across both Cursor and Claude Code. The same files run in either tool; nothing here is tied to one of them. Built for daily personal use first, public because it may help others.

## Install

The skills CLI installs skills directly from GitHub. Commands are not covered by the CLI, so those are a manual copy.

| Artifact | Install | Cursor | Claude Code |
| -------- | ------- | ------ | ----------- |
| `source` skill | `npx skills add manu-kaushik/agent-kit@source` | `~/.cursor/skills/source/` | `~/.claude/skills/source/` |
| `commit-message` command | manual copy | `~/.cursor/commands/` | `~/.claude/commands/` |

To install the skill by hand instead, copy `skills/source/` to the path for your tool. To install the command, copy `commands/commit-message.md` to the path for your tool.

Installing into both locations is fine and is not a conflict — they are separate tools reading separate directories.

## The `source` skill

SOURCE.md is the **persistent project record** — stack, architecture, decisions, deferrals, focus. Chats are temporary; SOURCE.md is not. Any agent in any chat reads it first and updates it when project truth changes.

The skill creates and maintains three files in the target project:

| File | Role |
| ---- | ---- |
| `SOURCE.md` | **Required** — the whole project on disk |
| `AGENTS.md` | Agent workflow; enforces SOURCE-first behavior |
| `CLAUDE.md` | Claude Code guidance; imports SOURCE via `@SOURCE.md` |

SOURCE.md is always included. The optional scope argument decides which guidance files come with it:

| Invocation | Creates in project root |
| ---------- | ----------------------- |
| `/source` | `SOURCE.md`, `AGENTS.md`, `CLAUDE.md` |
| `/source agents` | `SOURCE.md`, `AGENTS.md` |
| `/source claude` | `SOURCE.md`, `CLAUDE.md` |

Re-runs are safe. They bootstrap facts from the repository, merge durable knowledge from the current conversation, and prepend SOURCE pointers without erasing existing content. During normal work, agents update SOURCE.md whenever project facts change — not only when `/source` runs.

This repository's own [SOURCE.md](SOURCE.md), [AGENTS.md](AGENTS.md), and [CLAUDE.md](CLAUDE.md) were generated by running `/source` here.

### Scope is not install location

This is the single most confusing thing about the skill, so state it plainly: **where the skill is installed and which file it writes are two independent choices.**

| Axis | Controlled by | Effect |
| ---- | ------------- | ------ |
| Which tool runs the skill | Where it is installed — `~/.cursor/skills/` or `~/.claude/skills/` | None on behavior. The skill file is identical either way. |
| Which guidance file it writes | The scope argument — `/source`, `/source agents`, `/source claude` | Which of `AGENTS.md` / `CLAUDE.md` appears in the target project. |

Worked example: the skill installed at `~/.cursor/skills/source/` can still be run as `/source claude` to produce a `CLAUDE.md` for a teammate who uses Claude Code. The tool you are running and the file you want are separate choices.

## The `commit-message` command

`/commit-message` generates a Conventional Commits message for the currently staged changes and prints it in a fenced code block. It never runs `git commit` or any other write command — reviewing and committing stay with you.

If nothing is staged, it says so and stops.

## Skill vs subagent vs command

The deciding constraint is that **a subagent gets a fresh context window and only sees the prompt the parent hands it** — it cannot read the current conversation. Everything else follows from that.

| Artifact | Use when | Examples |
| -------- | -------- | -------- |
| Skill | Needs conversation context; injects knowledge or procedure into the main window | `source` — records decisions from the current chat |
| Subagent | Reads a lot, writes a little; the value is keeping that reading out of the main context | code review, issue triage, research |
| Command | Explicit user trigger, short deterministic procedure | `commit-message` |

## Layout

```
agent-kit/
├── skills/
│   └── source/
│       ├── SKILL.md
│       └── templates/
└── commands/
    └── commit-message.md
```

`skills/` at root is the standard container directory for the skills CLI, so discovery stops there. The CLI only matches files literally named `SKILL.md`, so `commands/*.md` is invisible to it — and the same will hold for `agents/*.md` when subagents land.
